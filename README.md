# Сайт для физики

## Запуск

Нужны JDK 17+, Maven 3.8+ и Node.js 20+

```bash
# бэк на http://localhost:8080
cd backend && mvn spring-boot:run

# фронт на http://localhost:5173, в другом терминале
cd frontend && npm install && npm run dev
```

Бэкенд по умолчанию стартует с профилем `dev` - база H2 прямо в памяти, ставить и настраивать ничего
не надо. Демоданные заливаются при каждом старте, посмотреть их можно в консоли
http://localhost:8080/h2-console (JDBC URL `jdbc:h2:mem:tutorsite`, юзер `sa`, пароль пустой)

Vite проксирует `/api` на бэкенд, так что CORS в разработке не мешает

Заходить можно двумя аккаунтами:

| Роль | Логин | Пароль  |
|---|---|---------|
| Админ | ney4s@tutorsite.local | ваш     |
| Ученик | student@tutorsite.local | student |

### На PostgreSQL

```bash
docker compose up -d postgres
cd backend && mvn spring-boot:run -Dspring-boot.run.profiles=
```

Пустой профиль выключает `dev` и возвращает настройки из `application.yml`. Собранный jar и
docker образ и так идут в постгрес, профиль `dev` прописан только в maven-плагине для удобства

Если постгрес уже стоит локально, контейнер не займёт порт 5432. Тогда либо создайте роль и базу руками

```bash
psql -d postgres -c "CREATE ROLE tutor WITH LOGIN PASSWORD 'tutor' CREATEDB;"
createdb -O tutor tutorsite
```

либо запускайтесь под своим системным пользователем: `DB_USER=$(whoami) DB_PASSWORD= mvn spring-boot:run`

### Всё в контейнерах

Сначала заполните переменные окружения, без них compose не стартует:

```bash
cp .env.example .env
```

Как минимум задайте `ADMIN_PASSWORD` и `JWT_SECRET`. Ключ подписи удобно сгенерировать так:

```bash
openssl rand -base64 48
```

Затем поднимайте:

```bash
docker compose --profile full up --build -d
```

Фронт соберётся и уедет под nginx на порт 3000, бэк и база поднимутся рядом

## Развёртывание на тестовом сервере

Нужен только docker с плагином compose. Порядок:

```bash
git clone <адрес репозитория> tutorsite && cd tutorsite
cp .env.example .env
```

Заполните `.env`: `ADMIN_PASSWORD`, `JWT_SECRET`, `DB_PASSWORD`. При необходимости смените
`WEB_PORT`, если 3000 уже занят. Дальше:

```bash
docker compose --profile full up --build -d
```

Первая сборка занимает несколько минут: maven тянет зависимости, фронт собирается вебпаком vite.
Готовность видно по `docker compose ps` - у backend должен появиться статус `healthy`. Только после
этого поднимается frontend, так что 502 на старте вы не поймаете.

Сайт откроется на `http://<адрес-сервера>:3000`. Учётные записи для показа:

| Роль | Логин | Пароль |
|---|---|---|
| Админ | значение `ADMIN_EMAIL` | значение `ADMIN_PASSWORD` |
| Ученик | student@tutorsite.local | student |
| Ученик | petrova@tutorsite.local | student |

### Важно про пароль администратора

Демоданные заливаются один раз - только в пустую базу. На постгресе с томом `pgdata` это значит,
что менять `ADMIN_PASSWORD` после первого старта бесполезно: пользователь уже создан. Если пароль
всё-таки нужно сменить, либо правьте запись в БД руками, либо пересоздавайте базу:

```bash
docker compose --profile full down -v && docker compose --profile full up --build -d
```

Флаг `-v` сносит том вместе со всеми данными - на боевой базе так делать нельзя.

### Обновить до свежего кода

```bash
git pull && docker compose --profile full up --build -d
```

Том с базой переживает пересборку, `ddl-auto: update` подтянет изменения схемы.

### Что стоит закрыть до показа заказчику

Наружу опубликован только веб-порт: постгрес и 8080 привязаны к `127.0.0.1`, снаружи их не видно.
Достучаться до них можно через ssh-туннель, например `ssh -L 8080:localhost:8080 user@server`.

По ТЗ (раздел 4, «Безопасность») требуется SSL. Сейчас его нет: сайт отдаётся по http.
Для демонстрации на тестовом сервере это обычно терпимо, но для приёмки нужен реверс-прокси
с сертификатом - caddy или nginx с certbot перед контейнером фронта.

## Что умеет

Публичная часть - главная с отзывами, «Обо мне», «Исследования», контакты. Тексты двух страниц
правятся из админки визуальным редактором

Каталог задач - лента карточек с формулами в LaTeX (рендерит KaTeX), встроенными видео-разборами
и ссылками на PDF. Фильтры предмет - ю класс -> сложность -> тема работают без перезагрузки страницы:
на бэке это динамические Specifications, на фронте обычный fetch с перерисовкой ленты

личный кабинет ученика - список назначенных заданий с дедлайнами, статусами и оценками, полоса
прогресса и форма отзыва. Отзыв не появляется на сайте сразу, а уходит на модерацию

Админка - таблица учеников (ФИО, класс, предмет, цели, оценки за ДЗ по 10-балльной шкале, прогресс,
заметки) с выгрузкой в xlsx, управление задачами с предпросмотром формул, модерация отзывов
и редактирование страниц

Роли три: гость, ученик и админ. Разграничение живёт и на бэке в Spring Security, и на фронте
в защищённых маршрутах, так что чужой раздел не откроется ни через интерфейс, ни запросом напрямую
